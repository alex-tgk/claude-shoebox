# Product Requirements Document Generator

Generate a comprehensive Product Requirements Document (PRD) for the product or feature described by the user.

## Instructions

Create a detailed PRD that includes:

### 1. Executive Summary
- Product name and brief description
- Problem statement and opportunity
- Target audience
- Key objectives and success metrics

### 2. Product Overview
- Vision and goals
- Key features and capabilities
- Value proposition
- User benefits

### 3. User Stories and Use Cases
- Primary user personas affected
- Detailed user stories (As a [user], I want [goal], so that [benefit])
- Key use cases and scenarios
- User journey maps

### 4. Functional Requirements
- Detailed feature specifications
- User interface requirements
- System behaviors and interactions
- Data requirements

### 5. Non-Functional Requirements
- Performance requirements
- Security and privacy considerations
- Scalability requirements
- Accessibility standards
- Browser/platform compatibility

### 6. Technical Considerations
- Architecture implications
- Integration requirements
- API specifications
- Data models and schemas

### 7. Design Requirements
- UI/UX principles
- Design system components
- Wireframes/mockups description
- Interaction patterns

### 8. Success Metrics
- Key Performance Indicators (KPIs)
- Success criteria
- Measurement methodology
- Target benchmarks

### 9. Timeline and Milestones
- Development phases
- Key milestones
- Launch timeline
- Dependencies

### 10. Risks and Mitigation
- Technical risks
- Business risks
- User adoption risks
- Mitigation strategies

### 11. Open Questions
- Unresolved issues
- Areas requiring further research
- Decisions pending

## Output Format

Provide a well-structured, professional PRD using clear headings, bullet points, and tables where appropriate. Include specific, measurable requirements rather than vague descriptions.

Ask clarifying questions if critical information is missing, then generate the complete PRD.
