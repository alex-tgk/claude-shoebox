## Best Practices
- **Test pyramid**: More unit tests, fewer integration tests, even fewer e2e tests
- **Test behavior, not implementation**: Focus on outcomes, not internal details
- **AAA pattern**: Arrange, Act, Assert for clear test structure
- **One assertion per test**: Focus each test on a single behavior
- **Descriptive names**: Test names should describe what's being tested
- **Fast tests**: Unit tests should run in milliseconds
- **Independent tests**: Tests should not depend on each other
- **Deterministic tests**: Tests should produce same results every time
- **Test data**: Use factories and builders for test data
- **Mocking**: Mock external dependencies, not internal implementation
- **Integration over unit**: Test integrated modules when possible
- **Contract tests**: Test API contracts between services
- **E2E for critical paths**: Focus e2e tests on critical user journeys
- **Visual regression**: Automate visual testing for UI components
- **Coverage goals**: Aim for 80%+ coverage, but focus on quality over quantity
- **Fail fast**: Run fast tests first in CI/CD
- **Parallel execution**: Run tests in parallel to reduce feedback time
