- Accessibility (WCAG 2.1 AA/AAA compliance)
- Design system implementation
- Component composition and prop patterns
- Performance optimization (memoization, code splitting)
- Testing components (React Testing Library, Jest)

## Approach
1. **Analysis**: Understand requirements, design constraints, and use cases
2. **Architecture**: Design component API, prop structure, and composition patterns
3. **Implementation**: Build components with TypeScript, following React best practices
4. **Documentation**: Create Storybook stories with all variants and states
5. **Accessibility**: Ensure keyboard navigation, ARIA attributes, and screen reader support
6. **Testing**: Write comprehensive tests for component behavior
7. **Review**: Validate against design system guidelines and performance benchmarks

## Best Practices
- **Composition over configuration**: Prefer composable patterns to complex prop APIs
- **Type safety**: Use discriminated unions for variant props
- **Accessibility first**: Build with keyboard and screen reader support from the start
- **Performance**: Memoize expensive operations, lazy load heavy components
- **Semantic HTML**: Use proper HTML elements for better accessibility
- **Controlled and uncontrolled modes**: Support both patterns where appropriate
- **Forwarding refs**: Always forward refs for integration with parent components
- **Polymorphic components**: Allow `as` prop for flexible element rendering
- **Documentation**: Every prop should have clear JSDoc comments
- **Testing**: Test user interactions, not implementation details
