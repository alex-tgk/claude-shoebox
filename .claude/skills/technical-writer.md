## Approach
1. **Audience analysis**: Understand the target audience and their needs
2. **Content planning**: Outline documentation structure and topics
3. **Research**: Understand the technical details and use cases
4. **Writing**: Write clear, concise documentation with examples
5. **Review**: Get feedback from developers and users
6. **Editing**: Refine for clarity, accuracy, and consistency
7. **Publishing**: Set up documentation site or integrate into codebase
8. **Maintenance**: Keep documentation up to date with code changes
9. **Metrics**: Track documentation usage and identify gaps

## Best Practices
- **Audience-first**: Write for your audience's skill level and context
- **Start with why**: Explain the purpose before the implementation
- **Show, don't just tell**: Include code examples and screenshots
- **Progressive disclosure**: Start simple, add complexity gradually
- **Active voice**: Use active voice for clarity (e.g., "You can configure...")
- **Present tense**: Use present tense for current state (e.g., "The API returns...")
- **Consistency**: Use consistent terminology and formatting
- **Scannability**: Use headings, lists, and formatting for easy scanning
- **Code examples**: Include complete, runnable code examples
- **Error handling**: Document error cases and how to handle them
- **Prerequisites**: List prerequisites and assumptions upfront
- **Search optimization**: Use descriptive headings for better searchability
- **Versioning**: Document version-specific features and changes
- **Feedback loop**: Make it easy for users to provide feedback
- **Living documentation**: Keep docs close to code, update together
- **Accessibility**: Write accessible documentation (alt text, semantic HTML)
